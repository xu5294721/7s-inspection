# 7S 巡检移动端 Apple 风格改造设计

## 1. 目标与范围

### 目标

以 Android 手机现场巡检为第一优先级，将现有 7S 巡检应用从“工程表单界面”升级为克制、清晰、接近原生 iOS 的移动端工作工具：

- 让用户打开应用后能快速继续或开始巡检。
- 让路线、项点、完成状态和照片数量一眼可辨。
- 让拍照成为巡检过程中的高权重主操作，但不遮挡检查内容。
- 统一首页、巡检、复核、历史和设置页面的视觉语言。
- 保留现有离线能力、IndexedDB 数据结构、照片处理、Word 生成和 Android 原生相册备份能力。

### 不在本次范围内

- 不更换 React、Vite、Capacitor 或 Lucide 技术栈。
- 不引入完整的第三方移动端组件库作为全局 UI 基础。
- 不调整数据库模型、路由数据、检查项数据或报告生成逻辑。
- 不将应用改造成营销型首页、数据大屏或桌面后台。

## 2. 设计原则

### 2.1 Apple 风格的具体含义

本次“Apple 风”指以下可执行的界面特征，而不是简单套用蓝色和大圆角：

- 浅灰系统背景与白色分组表面形成明确层级。
- 使用系统优先字体和更舒展的行高，减少密集边框。
- 通过分组列表、分段控制、底部操作栏和 Bottom Sheet 组织复杂功能。
- 主要操作只有一个视觉重点，次要操作降低对比度。
- 状态通过颜色、图标和短文本共同表达，不依赖颜色单独传达。
- 保持最小 44px 触控区域，适配 Android 安全区和现场单手操作。

### 2.2 品牌色策略

保留现有绿色作为 7S 巡检的品牌与安全主色，避免全盘复制 iOS 蓝色。采用浅灰、白色、深色文字、绿色主操作、橙色提醒、红色错误的多色状态体系，确保界面不会变成单一绿色主题。

## 3. 视觉系统

### 3.1 颜色 token

在 `app/src/styles/tokens.css` 中集中定义并由全局样式使用：

- `canvas`：接近 iOS grouped background 的浅灰色。
- `surface`：白色列表组、输入区和弹层表面。
- `ink`：主要文字。
- `muted`：辅助说明、时间、数量和非激活导航。
- `line`：低对比度分隔线。
- `accent`：现有绿色品牌色。
- `good`：已完成、正常状态。
- `reminder`：待处理、提醒状态。
- `assessment`：错误、考核和需要处理状态。

所有页面不得继续直接散落使用同一类硬编码颜色；业务状态可以使用语义 token。

### 3.2 字体与间距

字体优先使用：

```css
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
```

使用 4px 基础间距体系，页面内主要间距采用 8、12、16、20、24px。页面标题保持移动端可扫描的尺寸，不使用过大的营销型标题。

### 3.3 圆角、阴影和触控

- 分组容器：12-16px 圆角。
- 输入框和一般按钮：10-12px 圆角。
- 拍照等主操作：12-16px 圆角。
- 阴影仅用于浮层、底部操作栏和少数突出卡片，普通列表不使用厚重阴影。
- 所有主要交互控件的最小尺寸为 44px。
- 所有固定底部元素计算 `env(safe-area-inset-bottom)`。

## 4. 页面设计

### 4.1 AppShell

顶部保留应用名称和当前页面语境，改为轻量半透明或白色导航背景，降低顶部边框存在感。底部继续保留 5 个主导航入口：首页、巡检、历史、项点、设置；激活状态使用图标和文字颜色变化，不使用明显的绿色横线。

桌面端保持现有信息架构，在较宽屏幕上限制内容最大宽度，避免列表横向拉伸；不额外设计独立桌面后台。

### 4.2 首页

首页采用“标题 + 一张进度卡片 + 分组列表”的结构：

1. 页面标题和车间语境。
2. 一张“本周巡检进度”卡片，展示完成数量、进度百分比和进度条。
3. 分组列表中的“继续上次巡检”作为第一项，服务于现场连续工作。
4. 常用操作分组：开始新的巡检、本地数据备份。
5. 最近记录分组：展示最近巡检标题、时间、项点数量或通报状态。

进度卡片只保留一张，不添加多张统计卡，避免首页变成数据驾驶舱。

### 4.3 新建巡检

模板选择、路线选择和自定义路线保持现有功能，但改为分组列表和底部弹层：

- 模板版本以清晰的当前值展示，点击后在 Bottom Sheet 内选择。
- 路线列表显示名称、项点数量和选中状态。
- “全选、清空、自定义路线”作为低层级工具操作。
- “开始巡检”固定在底部操作栏，避免用户滚动后找不到下一步。

### 4.4 巡检中

巡检页是本次最重要的工作页面：

- 顶部显示当前巡检标题、路线和保存状态。
- 路线/项点区域使用分组列表，已完成项显示勾选状态和照片数量。
- 使用“全部 / 未完成 / 已完成”分段控制过滤项点。
- 检查结果编辑保留在项点内部，减少页面跳转。
- “拍摄现场照片”作为底部固定主操作；从相册选择、重拍、删除和标注作为照片组内次级操作。
- 进度信息使用简短文本，不使用大面积遮罩阻断现场操作。

照片处理、失败重试、相册备份和本地保存仍沿用现有逻辑，只调整承载它们的 UI 状态。

### 4.5 通报复核

- 顶部保留照片、奖励、考核等摘要，但改成轻量摘要条。
- 照片分类使用分段控制，替代多块按钮堆叠。
- 照片组保持网格展示，拖动手柄和考核字段收纳到组头或编辑弹层。
- 验证错误集中在“需补充内容”区域，并支持点击定位到具体项点。
- 生成 Word 是主操作；分享和下载为生成成功后的次级操作，放入底部操作区。

### 4.6 历史、项点、设置和弹层

这些页面沿用同一套 grouped list、输入控件、空状态和错误状态：

- 历史页使用日期/状态筛选和分组列表。
- 项点库与模板设置使用分组表单，编辑动作进入独立页面或 Bottom Sheet。
- 备份页强调数据安全、导出动作和最近备份状态。
- 确认操作优先使用底部弹层或轻量确认框，避免全屏厚重弹窗。

## 5. 组件与代码边界

优先在现有 CSS class 体系上演进，新增少量可复用 UI 组件，避免在本次任务中大范围重构业务文件：

- `AppShell`：顶部栏、底部 Tab、安全区布局。
- `GroupedSection` / `GroupedRow`：首页、历史、设置和选择列表的共同结构。
- `ProgressCard`：首页进度卡片。
- `SegmentedControl`：巡检过滤、照片分类等分段操作。
- `BottomActionBar`：新建巡检、巡检拍照、复核生成 Word 的固定操作栏。
- `BottomSheet`：模板、路线、排序和轻量编辑选择。

这些组件只负责视觉结构、交互状态和可访问性，不直接读取数据库，不改变检查数据。

## 6. 实施顺序

### 阶段一：视觉 token 与壳层

- 重做 `tokens.css` 和全局基础控件样式。
- 改造 `AppShell`、顶部栏、底部导航和安全区。
- 统一按钮、输入框、分组列表、浮层和状态消息。

### 阶段二：首页与新建流程

- 将 Dashboard 改为进度卡片和 grouped list。
- 将新建巡检改为分组选择和底部操作栏。
- 保留现有路由选择、模板和自定义路线逻辑。

### 阶段三：巡检中流程

- 调整路线、区域、项点和照片组的层级。
- 增加分段过滤视图。
- 将拍照主操作固定到安全区以上的底部操作栏。
- 保持照片处理、失败重试、相册保存和草稿保存行为不变。

### 阶段四：复核与次要页面

- 改造复核页照片分类、照片组、错误提示和 Word 操作。
- 统一历史、项点、设置和备份页面。
- 统一弹层、加载、空状态和错误状态。

## 7. 验收标准

### 视觉与响应式

- 390px、430px 手机宽度下无横向溢出、文字截断可接受、固定底部操作不遮挡内容。
- 768px 及以上宽度下页面保持可读的最大内容宽度。
- 颜色、圆角、间距、按钮和分组列表均来自 token 或公共样式。
- 首页、巡检中、复核三个关键页面视觉语言一致。

### 交互与可访问性

- 主要按钮和导航项触控区域不小于 44px。
- 键盘焦点、ARIA 标签、Tab 操作和错误定位不回退。
- Bottom Sheet、确认框和固定操作栏在 Android 安全区内正常显示。
- 拍照、重拍、删除、失败重试、数据保存和 Word 生成行为与改造前一致。

### 工程验证

- `pnpm lint` 通过。
- `pnpm exec vitest run --maxWorkers=1` 通过。
- `pnpm build` 通过。
- Android `assembleDebug` 通过。
- 使用 Playwright 或等效浏览器检查关键页面截图，确认没有遮挡、空白页面或布局漂移。

## 8. 风险与回滚

- 主要风险是 CSS 改造影响现有测试选择器和移动端底部固定元素；每个阶段应保持 class 名称兼容，必要时新增 class 而不是直接删除旧 class。
- 业务逻辑和数据结构不变，回滚可以按阶段恢复样式和页面组件提交。
- 不在本次任务中引入大型 UI 依赖，避免 Android 包体、构建和交互行为出现额外不确定性。
