# 7S 巡检 Apple 风格视觉系统与 APK 图标设计

## 1. 设计结论

本方案将 7S 巡检应用统一为“清透 iOS + 现场绿”的视觉方向：使用浅灰系统背景、白色分组表面、深色高可读文字、绿色主操作和低对比度分隔线，减少当前界面中偏网页表单的硬边框与密集控件。

本方案是视觉和交互表达层改造，不是功能改造。现有路由、底部导航、巡检流程、评价类别、拍照与相册、通报复核、Word 生成、历史记录、模板设置和备份恢复功能均保持不变。任何可能增加页面、入口、字段、统计指标或业务分类的设计，不属于本方案。

本文件作为后续 Luna 实现的视觉依据。若本文件与较早的 Apple 风格设计草案存在冲突，以本文件的“功能不变”和“视觉优先”边界为准。

## 2. 当前问题判断

### 2.1 APK 图标

当前图标使用轨道、斜线和“7S”组合，能够表达铁路和 7S，但线条数量较多，缩小到 Android 桌面图标尺寸后容易出现视觉拥挤，主体也不像一个简洁的移动应用图标。

### 2.2 应用界面

当前视觉基线已经具备浅色背景、绿色主色、44px 触控尺寸和底部导航，但整体仍有以下观感问题：

- 控件和列表使用了较多完整边框，页面容易像后台表单。
- 圆角层级不够统一，按钮、输入框、分组容器和照片卡片缺少共同规则。
- 底部导航的激活状态使用顶部色条，较像网页导航，不够接近原生移动端。
- 普通列表、重点操作、提示状态和弹层之间的视觉层级不够明显。
- 绿色、橙色和红色状态色需要从“大面积着色”收敛到“局部语义提示”。

## 3. 视觉方向

### 3.1 关键词

清透、克制、分组、留白、快速识别、单手操作、现场可靠。

Apple 风格在本项目中具体表现为：

- 使用浅灰 grouped background 和白色 grouped surface。
- 使用分组列表、轻量分隔线和明确的标题层级组织信息。
- 主操作只有一个视觉重点，次要操作降低对比度。
- 通过图标、颜色和文字共同表达状态，不仅依赖颜色。
- 使用系统字体和轻微层次，不引入外部在线字体或重型 UI 框架。
- 毛玻璃只作为可选增强，必须有纯色背景回退，保证 Android WebView 表现稳定。

### 3.2 品牌表达

不直接复制 Apple 标志、SF Symbols 图形或专有视觉资产。使用接近 iOS 的布局和层级方法，同时保留深绿色作为铁路现场 7S 工具的品牌识别色。

## 4. APK 图标设计

### 4.1 图标名称与含义

图标概念命名为“轨道勾”。它由两条简化轨道和一条向右上延伸的圆角勾线组成，同时表达：

- 轨道作业和铁路现场。
- 7S 巡检路线。
- 检查确认和问题闭环。

### 4.2 图形结构

- 采用 Android 自适应图标的圆角方形背景。
- 背景使用深绿色单色或非常克制的同色渐变，建议从 `#087456` 过渡到 `#064B3D`。
- 前景使用白色圆角线条，不放“7S”文字，避免小尺寸下文字糊成一团。
- 轨道线和勾线使用圆角端点、圆角连接，线宽保持一致。
- 图形主体控制在自适应图标安全区内，建议占画布宽度的 58%～68%。
- 在 48px、72px 和 108px 的预览尺寸下，轨道和勾线仍应能被一眼识别。
- 图标不能依赖透明背景才能成立；圆形裁切、圆角裁切和普通方形显示都应保持完整。

### 4.3 资产范围

后续实现时统一更新以下资产，不改变应用包名：

- Android adaptive icon foreground/background。
- 各密度 `mipmap` 图标和 round 图标。
- `app/resources/icon-only.png` 源图标。
- PWA 的 `icon-192.png`、`icon-512.png` 和 maskable 图标。
- `favicon.svg` 或等效浏览器图标。

启动页可以沿用同一深绿色背景和白色“轨道勾”主体，但不增加额外文字和装饰。

## 5. 视觉令牌

建议集中更新 `app/src/styles/tokens.css`，页面样式只引用语义变量。

### 5.1 颜色

```css
--color-canvas: #f2f2f7;
--color-surface: #ffffff;
--color-ink: #1c1c1e;
--color-muted: #8e8e93;
--color-border: #d1d1d6;
--color-accent: #087456;
--color-good: #2f855a;
--color-reminder: #b7791f;
--color-assessment: #b23a3a;
```

状态色只用于状态标签、选中状态、提示条、图标背景或小面积边线，不用于整块页面背景。现有评价类别和业务标签的数量、文字、数据结构保持原样。

### 5.2 字体与间距

```css
font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

不下载在线字体，确保离线使用稳定。建议使用 4px 基础间距，常用值为 8、12、16、20、24px。

- 页面主标题：22～24px。
- 分组标题：15～17px。
- 普通行标题：15～16px。
- 正文和输入内容：15～16px。
- 辅助信息：12～13px。
- 行高保持 1.45～1.6，中文说明避免过度压缩。

### 5.3 圆角、边框与阴影

- 普通输入框和按钮：10～12px。
- 分组容器和照片区域：14～16px。
- Bottom Sheet 顶部：24px。
- 胶囊标签和分段选择：999px 或完全圆角。
- 普通列表不使用厚重阴影，以分组、留白和分隔线表达层级。
- 浮层、Bottom Sheet 和固定操作栏使用非常轻的阴影。
- 所有主要交互区域最小 44px，并适配 `env(safe-area-inset-bottom)`。

## 6. 页面视觉与交互规则

### 6.1 AppShell 与底部导航

- 保留现有五个底部导航入口和文字。
- 顶部栏使用白色或轻微透明白色，降低底部边框存在感。
- 当前导航项使用绿色图标/文字加浅绿色胶囊背景，不再使用顶部绿色横线。
- 非当前导航项使用灰色图标和文字。
- 底部导航保留安全区，毛玻璃不可用时回退到不透明白色。

### 6.2 首页

- 保留现有“开始巡检”和备份提醒功能。
- 开始巡检作为页面唯一主视觉操作，使用绿色主按钮或绿色主操作区。
- 备份提醒使用浅黄色提示条，关闭按钮保持独立且不抢主视觉。
- 不额外增加统计卡、进度指标、最近记录或新的首页入口，除非这些内容已经属于现有功能。

### 6.3 新建巡检与路线选择

- 模板选择、路线选择、全选、清空和自定义路线继续使用现有流程。
- 路线列表改为 grouped list，选择状态使用圆形勾选或系统风格选中标记。
- 工具操作使用低对比度次按钮，开始巡检保持底部固定主操作。
- 固定底部操作栏始终位于安全区之上，不遮挡最后一项路线内容。

### 6.4 巡检页面

- 搜索框改为浅灰或白色圆角搜索条，减少硬边框。
- 路线、区域和检查项保持现有层级，用缩进、间距和轻分隔线表达父子关系。
- 已完成状态使用绿色勾或小圆点，同时保留文字和照片数量等辅助信息。
- 检查项点击后继续打开现有编辑 Sheet，不改变编辑内容和保存行为。
- 拍照、相册两个主入口保持等宽、等高、同层级；相册、重拍、删除、标注等操作降为照片组内次级动作。
- 照片缩略图使用 12～14px 圆角，避免每张照片都呈现为厚重卡片。

### 6.5 评价编辑与照片分类

- 现有评价类别和内容编辑逻辑完全保留。
- 分类选择改为统一的分段选择器或状态标签。
- 正常、提醒、考核等状态使用各自语义颜色，但只在选中项、标签和提示区域显示。
- 责任人员、金额、描述和后续整改等字段仍使用现有字段，不新增业务字段。

### 6.6 通报复核

- 顶部摘要改为轻量汇总条，不使用多个厚重统计卡。
- 分类切换、排序、项点编辑和照片编辑保持现有入口，统一为分段控件、图标按钮和 Bottom Sheet。
- 验证错误集中在清晰的提示区域，并保留现有定位和修复行为。
- 生成 Word 保持唯一主操作；下载、分享和生成后的结果操作作为次级动作。

### 6.7 历史、项点、设置与备份

- 历史记录、项点库和设置入口统一使用 grouped list。
- 每个设置入口使用“图标容器 + 标题 + 说明 + 右侧箭头”的结构。
- 表单按功能分组，不把每个字段单独做成卡片。
- 备份页面强调“本地数据安全”和导出/恢复状态，但不新增云端同步或账号入口。
- 删除、彻底删除和恢复等高风险操作保留现有确认流程，统一为清晰的危险操作样式。

### 6.8 弹层、错误和状态

- 编辑、排序和选择类弹层优先使用 Bottom Sheet。
- Bottom Sheet 具备顶部拖动提示、标题、滚动内容区和底部安全区按钮。
- 加载、成功、提醒和错误提示使用统一提示条或状态区域。
- 错误文字要与现场操作相关，避免只显示技术错误。
- 保留现有 ARIA 标签、键盘焦点、关闭后焦点回退和触控区域。

## 7. Luna 实现边界

### 必须保持不变

- React、Vite、Capacitor、Lucide 和本地 IndexedDB 架构。
- 现有路由、底部导航入口和页面功能。
- 巡检记录、照片、评价、模板、Word 生成和备份恢复的数据模型。
- 照片保存、相册同步、失败重试和本地优先行为。
- 现有评价类别、文字和业务字段。

### 允许调整

- `tokens.css` 中的颜色、圆角、间距、字体和阴影变量。
- `global.css` 中的布局、按钮、输入框、列表、导航、弹层和安全区样式。
- 页面 JSX 的视觉包裹结构和 class 组合，但不改变业务处理函数的语义。
- 现有 Lucide 图标的大小、颜色、容器和排列方式。
- Android、PWA、favicon 和启动页图标资源。

### 不允许引入

- 新页面、新导航入口、新业务分类、新统计指标或新的云端能力。
- 外部在线字体、重型 UI 组件库或会影响离线使用的网络资源。
- 直接复制 Apple 标志、SF Symbols 私有资源或未经许可的品牌资产。

## 8. 验收标准

### 视觉验收

- 首页、巡检中、通报复核、历史和设置页面使用同一套背景、分组、按钮、输入框和状态语言。
- 390px 和 430px 宽度下无横向溢出，固定底部操作不遮挡内容。
- 768px 以上宽度下内容保持合理最大宽度，不被拉成桌面后台布局。
- 主要控件触控区域不小于 44px，文字和状态颜色保持可读对比度。
- 普通列表没有明显的边框堆叠和重阴影。

### 图标验收

- APK 自适应图标、round 图标、PWA 图标和 favicon 使用同一视觉概念。
- 48px、72px、108px 预览下主体仍能识别为“轨道 + 检查勾”。
- 圆形、圆角方形和普通方形裁切均不切断主体。
- 图标不含难以识别的小字，不依赖透明背景才能看清。

### 功能回归

- 不新增、不删除现有功能。
- 拍照、相册选择、重拍、删除、标注、评价保存、排序、Word 生成、备份恢复行为与改造前一致。
- `pnpm lint`、Vitest、`pnpm build` 和 Android debug 构建通过。
- 使用移动端视口检查首页、巡检中、复核、设置和弹层状态，确认没有底部遮挡或安全区错位。

## 9. 推荐实施顺序

1. 先重做视觉令牌和全局基础控件。
2. 再统一 AppShell、顶部栏、底部导航和安全区。
3. 接着处理首页、路线选择、巡检页和照片评价编辑。
4. 然后处理通报复核、历史、项点、设置和备份页面。
5. 最后制作“轨道勾”图标并同步 Android、PWA、favicon 和启动页资源。
6. 每个阶段完成后进行移动端视觉回归和功能回归。
