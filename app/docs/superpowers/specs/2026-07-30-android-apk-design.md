# 7S巡检 Android APK 设计

## 目标

将现有 7S 巡检 PWA 封装为可独立安装的 Android APK。APK 安装后不依赖电脑、局域网或互联网即可启动，现场可离线完成巡检、拍照、评价、数据保存和 Word 通报生成。

首个版本面向用户本人试用，支持 Android 10 及以上设备。应用名称为“7S巡检”。

## 技术方案

采用 Capacitor Android 容器承载现有 React、Vite 应用：

- Vite 构建产物随 APK 一起打包，不从电脑或网络加载页面资源。
- 现有 Hash Router、业务模块、DOCX 生成逻辑和 IndexedDB 数据结构保持不变。
- Capacitor WebView 通过本地地址加载应用，应用冷启动时无需访问服务器。
- Android 工程使用稳定的应用包名，后续试用版升级时保持相同包名和签名。
- 应用包名固定为 `com.xiangtang.sevensinspection`。
- 首版生成可直接安装的个人试用 APK，不接入应用商店、账号系统或云端服务。

不采用普通远程 WebView，因为它仍依赖网页服务，并且 Blob 下载、相机和离线启动兼容性不足；不重写原生界面，因为现有业务功能已经完整，重复开发风险和成本过高。

## 离线数据

- 巡检记录、路线模板、检查内容、评价、照片元数据和 Word 模板继续存放在手机 WebView 的 IndexedDB 中。
- 照片原图和缩略图继续以 Blob 形式保存在本地数据库中。
- 关闭应用、重启手机或断网后，数据仍可读取。
- 正常安装同包名、同签名的新版本时保留数据。
- 卸载应用或在系统设置中清除应用数据会删除本地巡检数据，因此保留现有 ZIP 备份与恢复功能。
- APK 不自动上传照片、巡检记录或生成的 Word。

## 拍照与相册

- 保留现有“拍照”和“从相册选择”入口。
- “拍照”继续优先调用后置摄像头；“相册选择”允许批量选择照片。
- Android 工程声明相机及文件选择所需的最小权限。
- 继续使用现有图片压缩、缩略图、标注和质量选择逻辑，避免 APK 与网页版产生两套照片处理流程。
- 用户拒绝相机权限时，页面显示明确提示，并允许改用相册选择；不得导致巡检记录损坏。

## Word 与备份文件输出

新增统一的文件输出适配层，业务层只提交 Blob、文件名和 MIME 类型：

- 浏览器环境继续使用现有网页下载和 Web Share 行为。
- Android APK 环境通过 Capacitor 原生桥接输出文件。
- “保存”把 Word 写入公共下载目录下的“7S巡检”文件夹，并返回明确的成功位置或失败原因。
- “分享”把临时文件交给 Android 系统分享菜单，可选择 WPS、微信、文件管理器等已安装应用。
- ZIP 备份使用相同输出适配层，能够保存到下载目录；恢复继续使用系统文件选择器导入 ZIP。
- 临时分享文件写入应用缓存，可在分享完成后或由系统按缓存策略清理。
- 同名文件不静默覆盖，使用系统支持的唯一名称策略保留两个文件。
- 原有 Word 内容、照片排版、正文格式和“不生成附表”的规则保持不变。

Android 10 及以上使用系统的公共下载存储接口，不申请“管理所有文件”这类过度权限。

## 启动与升级

- APK 启动直接进入现有巡检应用，不显示远程服务器地址或网络错误页。
- PWA 更新提示在 APK 环境中隐藏；APK 版本通过重新安装新 APK 更新。
- 首个个人试用版使用固定调试签名构建。后续正式发布版如更换签名，必须先在旧版中导出 ZIP 备份，再卸载旧版、安装正式版并恢复备份。
- Android 返回键按 WebView 历史记录返回；没有可返回页面时退出应用。

## 错误处理

- 原生文件保存或分享失败时，不把巡检状态误标记为已成功导出，并向用户显示可执行的中文错误提示。
- Word 已生成但保存失败时，保留当前巡检数据，允许重新保存或改用分享。
- 存储空间不足、权限被拒绝、目标应用不存在和文件名冲突分别返回可识别结果。
- Android 原生桥接不可用时，网页版仍走现有浏览器输出，不影响电脑端使用。
- 应用崩溃或被系统杀死后，已完成的 IndexedDB 事务保持有效，未完成操作按现有事务机制回滚。

## 工程与构建环境

当前电脑缺少 Java、Android SDK、ADB 和 Gradle。实施阶段需要：

- 使用 Capacitor Core、CLI 和 Android `8.4.2`；当前 Node `24.16.0` 满足其 Node 22+ 要求。
- 安装 Capacitor 8 要求的 Android Studio `2025.2.1` 或更新版本，并使用其内置 JDK。
- 安装 Android SDK Platform 36、对应 Build Tools 和 Platform Tools；应用 `minSdkVersion` 固定为 29，`compileSdkVersion` 和 `targetSdkVersion` 固定为 36。
- 由项目 Gradle Wrapper 固定 Gradle `8.14.3`，不依赖全局 Gradle。
- 新增 Capacitor 配置和 `android/` 工程，Web 资源目录指向 `dist/`。
- 通过项目脚本完成 Web 构建、Capacitor 同步和 APK 构建，降低后续重复构建难度。

## 验证标准

自动验证包括：

- 现有 TypeScript、lint、Vitest、构建和手机尺寸 Playwright 测试全部通过。
- 文件输出适配层测试覆盖浏览器回退、APK 保存、APK 分享、取消和失败路径。
- APK 可由 Gradle 成功构建，Android lint 和可执行单元测试通过。
- 检查 APK 内包含当前 Vite 构建产物，不引用 `192.168.*`、`127.0.0.1:4175` 或其他远程开发服务器。

真机验收包括：

1. 在 Android 10 及以上手机安装 APK。
2. 关闭电脑并关闭手机网络后，冷启动应用。
3. 新建巡检，调用后置摄像头拍照，并从相册批量选图。
4. 完成好的方面、提醒问题和考核问题评价。
5. 关闭并重新打开应用，确认巡检和照片仍存在。
6. 离线生成 Word，保存到“下载/7S巡检”，使用 WPS 打开。
7. 调用系统分享菜单分享 Word。
8. 导出 ZIP 备份，并使用该备份完成恢复验证。

## 不在首版范围

- iOS 安装包。
- 多人账号、云同步、电脑与手机自动同步。
- 应用商店发布、在线更新和消息推送。
- 后台自动上传、远程数据库和服务器端 Word 生成。
- 重写现有巡检界面或业务流程。
